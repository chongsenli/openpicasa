## 0. 核心判断：手机是「压缩」，展开是「解压」

`docs/19` §0 已经论证过：桌面端是「鼠标 + 大窗口 + **三行骨架**（顶栏 / 左栏树 + 主区 / 状态栏）」（`docs/11` §2.1、`docs/10` M32-UI-04），
手机因纵向空间与无鼠标，**被迫把常驻左栏压成底部 3 Tab、把信息面板压成上滑 bottom sheet、把框选压成长按多选**。

折叠屏展开后，这些约束一次性消失。**展开态不该是把手机界面等比拉宽**（那会得到「巨大的手机」：3 Tab 拉到 800dp、栅格稀疏、上方大片留白），
而应**逆向执行那次翻译**，把压下去的层级放回来，回到桌面骨架的同构形态：

| 手机（`19`，COMPACT） | 折叠展开态（本文，MEDIUM/EXPANDED） | 桌面（`11`/`10`） | 为什么 |
| --- | --- | --- | --- |
| 底部 3 Tab：照片 / 文件夹 / 索引 | **常驻 Navigation Rail（72dp）** | 左栏常驻树 | Rail 是大屏 M3 的标准紧凑导航，不占主区宽度 |
| 「文件夹」Tab 全屏列表 | **List–Detail 左窗格常驻列表** | 左栏文件夹树 + 收藏 | 展开后列表与内容可同时可见，不再需要来回跳 |
| 上滑 bottom sheet（EXIF / 标签） | **Supporting pane 右窗格常驻** | 主区侧栏 / 属性区 | 展开态最大收益：信息不再遮挡照片 |
| 折叠筛选面板 | **左窗格常驻筛选器** | 顶栏筛选面板 | 组合筛选常驻，边调边看结果 |
| 长按多选 + 底部 CAB | **框选 / 点选 + 顶部 CAB + 跨窗格拖拽投放** | 框选（`14` §4）+ 左栏托盘 | 展开态有指针 / 触控板与更大命中区 |
| 全屏查看器（单窗格） | **左大图 + 右常驻信息**，或 Flex 上大图下胶片 | 全屏查看器 | 手势保留，信息面板常驻 |
| 索引 Tab 全屏页（滚动长页） | **左任务/目录列表 + 右六态详情** | 索引管理窗口（五标签） | 长页拆成主–从，失败清单常驻可见 |
| FAB（添加文件夹 / 新建） | **Extended FAB（带文字）** | 顶栏按钮 | 大屏空间足够，图标 FAB 语义弱 |

> 因此本文与 `19` 是**同一套信息架构的两个宽度档**，不是两套产品：`MgmtSnapshot` 仍是唯一真相源，
> 索引数字在 Rail 角标 / 列表行 / 详情摘要 / 状态栏四处同源（`docs/11` §2.1.2「五处读同一份快照」的大屏变体）。

## 1. 平台假设与设计基线（探讨口径）

> 这些是**设计假设**，不是已裁决需求；若立项，需按 `15`/`16` 的 P 项流程逐条裁决。

### 1.1 尺寸类与参考画布

| 项 | 假设值 | 依据 / 影响 |
| --- | --- | --- |
| 宽度类 | **折叠外屏 = COMPACT（< 600dp）**；**书本式内屏展开 ≈ MEDIUM（600–839dp），逼近 EXPANDED 边界（≥ 840dp）** | Galaxy Z Fold / Pixel Fold 展开内屏约 800–840dp 宽，不是平板宽度；按 M3 WindowSizeClass 取 MEDIUM，但允许启用 EXPANDED 的 List–Detail |
| 参考画布 | **800 × 720 dp**（≈ 书本式 4:3 内屏，约 2200 × 1840 px @2.75x） | HTML 原型按 880 × 682 px 外框绘制；比手机 360 × 780dp 更「方」 |
| 折痕方向 | **书本式：竖向中缝**（展开平铺）；**半折叠：横向中缝**（桌模式 Flex） | 双屏 / 外折设备的折痕方向不同，见 P-F05 |
| 折痕避让带 | **中缝两侧各 24 dp（共 48dp）** | 见 §5；比常见的 16dp 更保守，因为照片网格命中区大 |
| 设计语言 | **Material 3 大屏规范**：Navigation Rail、List–Detail / Supporting pane 规范布局、Extended FAB、Side sheet | 沿用 `19` 的单色主题（动态取色默认关），不恢复玻璃态、不引彩色顶栏底图 |
| 图片来源 | **MediaStore + SAF 只读**（R-1） | 与 `19` 一致；展开态不因多窗格增加任何写权限 |
| 深色主题 | 跟随系统（待裁决 P-F03），本原型只画浅色一版；**查看器仍为暗底** | `12` §11 曾把深色主题列为非目标 |

### 1.2 三种姿态

| 姿态 | 折痕 | 布局 | 对应屏幕 | 与 `19` 的关系 |
| --- | --- | --- | --- | --- |
| **A · 展开平铺 Flat** | 竖向中缝 | 双窗格（List–Detail / Supporting pane）+ Rail | **U1–U6** | 手机 10 屏的「解压」形态 |
| **B · 桌模式 Flex（半折叠 / 帐篷）** | 横向中缝 | 上半屏内容 + 下半屏控制甲板 | **F1** | 折叠屏独有，手机 / 桌面都没有 |
| **C · 折叠态 Folded** | 外屏 | 单窗格 + 底部 3 Tab | **`19` 的 S1–S10** | 直接回退，不新画；原型里给出跳转入口 |

三个姿态是**同一任务的连续状态**，不是三个 Activity：见 §6。

> 等宽示意；`┊` = **物理折痕（竖向）**，`┈` = **物理折痕（横向）**，`░` 缩略图占位，`★` 星标，
> `[ ]` 控件，`●` 角标，`≡` 菜单，`＋` FAB，`▁` 手势条，`◧` Navigation Rail。
> 展开屏宽 ≈ 800dp；左 Rail 72dp，左窗格 333dp，折痕避让带 48dp，右窗格 405dp（合计 858dp 玻璃区，外框 880px）。

## 5. 折痕（铰链）设计规范

> 这是本文相对 `19` 与桌面文档**唯一全新的设计约束**。书本式折叠屏有条物理中缝，
> 展开平铺时竖向、桌模式时横向；屏幕在缝处有曲率、反光、可能的触控盲区与分屏缝隙。

### 5.1 避让带

| 项 | 值 |
| --- | --- |
| 避让带宽度 | 中缝两侧各 **24 dp**（合计 48dp） |
| 展开平铺 | 竖向带 `x ∈ [W/2 − 24, W/2 + 24]` |
| 桌模式 Flex | 横向带 `y ∈ [H/2 − 24, H/2 + 24]` |

### 5.2 禁放清单（避让带内一律不得出现）

- 按钮 / FAB / chip / 开关 / 下拉框 / 任何可点击控件的**命中区**；
- **可拖拽的窗格分隔手柄**（拖动时手柄可能被折痕吞掉，且跨缝拖动体验差）；
- 单行连续文本（标题、文件名、EXIF 值、失败原因、toast 文案）；
- 选中计数、索引数字、进度百分比、状态栏数字；
- 日期分组头、面包屑等**横跨两窗格**的条带；
- 对话框、bottom sheet / side sheet 的边缘（其定位锚点也不得落在避让带内）。

### 5.3 允许落在避让带里的内容

- 纯背景 gutter（本文用 `--hinge-gutter` 底色）；
- 照片栅格的**列间隙**（缩略图边缘可进入，但缩略图命中区不进入）；
- 窗格之间的空白分隔、阴影、发丝线；
- 折痕本身的视觉表现（细线 + 两侧极淡阴影），仅作示意。

### 5.4 双窗格分隔线不压缝

U1–U6 的 List–Detail 分隔**不是**直接画在中缝上：
左窗格右缘到中缝留 24dp，右窗格左缘到中缝留 24dp，中缝从 48dp 的 gutter 正中穿过。
若支持拖拽调宽，手柄放在 gutter 内、距中缝 ≥ 24dp，且**拖拽时右窗格最小宽度不得低于 320dp**（低于则自动折叠成抽屉，见 P-F01）。
桌模式 F1 同理：上窗格底边 / 下窗格顶边各退 24dp，折痕从中间空白带穿过；**上半屏不放任何控件**。

### 5.5 姿态识别失败时

若系统无法给出铰链位置（外折设备、双屏设备、模拟器），**退化为普通 MEDIUM 布局**：
Rail + 单窗格 + 抽屉，不画折痕、不做双窗格（见 P-F05）。宁可少一栏，也不把控件压在可能的缝上。

## 6. 姿态切换与连续性

折叠 / 展开在 Android 是 **configuration change**（`WindowSizeClass` 变化），不是新页面、不是新任务：

| 场景 | 要求 |
| --- | --- |
| 展开 ↔ 折叠 | 不重建索引任务；不重置栅格滚动位置、搜索词、筛选条件、选中集、当前照片序号 |
| U2 ↔ 手机 S6 | 右常驻信息面板 ⇄ 上滑 bottom sheet，**同一份 EXIF / 标签数据**；正在编辑的标签输入不丢 |
| U4 ↔ 手机 S5 | 框选/拖拽 ⇄ 长按多选/CAB；已选集合保留 |
| U5 切姿态 | 六态进度、失败清单、离线节点**原样保留**；进度不显示 ETA |
| Rail ⇄ 底部 3 Tab | 当前导航目标映射：照片→照片、文件夹→文件夹、相册→照片 Tab 的相册分段、索引→索引 |
| 桌模式 Flex ↔ Flat | 当前照片序号、缩放级别、信息面板开合态保留 |
| 一向禁止 | 不因姿态切换产生「已完成 / 已取消」的假状态；不把后台任务静默停掉 |

> 这直接继承 `12` §0.2「关闭 ≠ 取消任务」与 `18` 的任务恢复语义，是**比布局更重要的正确性要求**。

## 10. 红线与非目标

**逐条继承 `README.md` / `19` §10 的产品内核**：

- **R-1 照片目录零写入**：MediaStore / SAF 只读；不写 `.picasa.ini`、不改原图 mtime / 不移动 / 不删除原图；数据只落自家 App 私有目录。拖拽投放只改自家数据库关系。
- **R-2 编辑室入口不存在**：U2 / F1 均**无**编辑 / 滤镜 / 旋转写回入口；方向只由 EXIF Orientation 决定。
- **R-3 装得上打得开**：姿态切换是 configuration change，不得因展开 / 折叠崩溃或丢状态。
- **单一真相源**：索引 / 选中 / 托盘数字来自同一份 `MgmtSnapshot`。
- **失败不静默 / 不显示 ETA**：进度只给「已处理 N / M」。
- **不恢复玻璃态**（`docs/ui-baseline/README.md` R-M42-3）、不引彩色顶栏底图、不引原版 Picasa 资源。

**非目标（本版不做）**：

1. 不画平板（≥ 840dp EXPANDED）专属布局 —— 折叠展开态按 MEDIUM 处理，平板可复用但需另做 Navigation Drawer 版。
2. 不画外折 / 双屏 / 卷轴屏设备的折痕方案（P-F05）。
3. 不承诺复用桌面 Rust 引擎 —— 与 `19` 一致，Android 侧索引实现未定。
4. 不做多窗 / 多实例 / 拖拽跨应用（Android 拖放协议）细化。
5. 不做深色主题一版（P-F03）、不做动态取色一版。
6. 不把「桌面模式 Flex」做成可写回的编辑台 —— 下半屏只有浏览 / 整理 / 查看信息。
