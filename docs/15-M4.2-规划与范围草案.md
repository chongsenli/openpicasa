## 0. 里程碑定位

### 0.1 从 M4.1 到 M4.2 的接力
- **M4**（0.4.0-beta.x）：照片检索、整理、索引管理、DB v8、索引导入导出。
- **M4.1**（0.4.1-Beta2，v1.0→v1.8）：一次**展示层 + 交互层修复**——工具栏四按钮与双态、三布局圆角贴图、密度、右键菜单退役、筛选收口、点击多选/空白清空、框选拖选；中途做了一整套玻璃态又在 v1.7 整体回退，v1.8 仅「加深按钮阴影」。数据层零改动。
- **M4.2（本版）**：**不新造大机制**，把 M4 / M4.1 迭代中「为了守住红线、或因为工作量/技术可行性」而**明确顺延、诚实登记为未完成**的展示与健壮性欠账清偿掉，让用户「看得到、选得顺、用得稳」。定位为：**展示打磨 + 展示性能（图片加载速度 / 滑动平滑度）+ 欠账清偿 + 发布收口**，是 M4 系列走向 12-RELEASE 前的小版本，**不是 M5（标记+相册）/ M6（排版+查看器）**。

> 定位边界：M5 的「独立相册 / 标记」、M6 的「排版 / 查看器 / 时间轴全屏视图」不在本版。本版只做「已经记在账上、且属于展示层/交互层/健壮性」的收尾。
>
> ⚠️ **展示性能（D 组，用户 2026-11-08 m00172 追加）** 是 M4.1「展示速度」主题域的正向延续，但**不是改常量硬提参数**：M4.1 把 `TEX_UPLOAD_PER_FRAME=3` / `TEX_CACHE_CAP=120` / `SCROLLBAR=8.0` 锁死成红线（R-M41-2）正是为了守住 p99 ≤ 25 ms。D 组的目标是**在不动这些基线常量的前提下，把「出图延迟」和「滚动掉帧」从"能用"做到"顺滑"**；任何要动常量/引入每帧重绘的做法，都须先经 P-M42-09 裁决并复核基准，不能默认放行。

### 0.2 为什么是这些候选（立项依据四处）
1. **M4.1 `docs/13` §8 非目标表**：明确把「框选边缘自动滚动、跨页框选、触板手势框选」「微缩图集（≤48px）圆角」「macOS 原生 vibrancy」「列表/深色主题」等顺延。
2. **M4.1 `docs/13` §7 P 项 / §10.3 已知偏离表**：`P-M41-09`（框选边缘滚动顺延 M4.2）、`P-M41-04`（微缩图集圆角顺延）、「批量标签浮层三态查询 O(标签数) 次查库」「右键 `out.context` 字段可在 M4.2 清理」、§10.5「真·屏幕空间折射 1~2 周顺延 M4.2」。
3. **M4 交接 / beta.2 release notes**：星标角标在网格与查看器不显示、左栏「＋新建标签/相册」只弹提示、相册 CRUD（改名/删除/加入照片下拉）未接 UI、F1-07 导入向导缩略图预览未实装、索引导入导出百万级后台线程化留后续、P-M4-01～09 待裁决、Linux/Xvfb GUI 回放环境缺失、epaint 崩溃精确 Shape 来源无 backtrace。
4. **用户 2026-11-08 追加（m00172）**：「M4.2增加图片加载速度，和图片滑动更平滑展示」——这是**用户直接提出的正向体验目标**，不属于「顺延欠账」，单列为 **D 组 · 展示性能**（§1.2 / §3），来源记为用户诉求，立项依据是 M4.1 已建立的展示速度基线与红线（R-M41-2 / R-M42-1），避免与「欠账清偿」混为一谈。

### 1.2 推荐纳入（分四组，详见 §3）
- **A 展示欠账（用户肉眼可见，优先）**：星标角标与标签在网格/查看器显示、微缩图集（≤48px）圆角、查看器信息条补齐星标/标签。
- **B 交互欠账（选中与框选顺延项）**：框选边缘自动滚动、跨页框选、触板手势框选；左栏「＋新建标签/相册」接真逻辑；相册改名/删除/加入照片下拉；星标/标签浮层查询收敛。
- **C 健壮性与发布收口（不显眼但挡发布）**：索引导入导出百万级后台线程化、F1-07 导入向导选前缩略图预览、epaint 崩溃精确 Shape 来源、GUI 回放验收环境、右键 `out.context` 字段清理、批量标签浮层三态缓存、P-M4-01～09 / P-M41-01·03 口径归档、docs/ui-baseline 与 `03` 补登记、门禁与隔离短跑复验。
- **D 展示性能（用户 2026-11-08 追加，正向体验目标）**：**图片加载速度**（首张出图更快、空白格更少）、**图片滑动/滚动更平滑**（掉帧更少、滚动不抖）；前置 `M42-PERF-00` 基准与埋点。范围受 R-M42-1 强约束——**默认不改已锁死常量**（`TEX_UPLOAD_PER_FRAME=3` / `TEX_CACHE_CAP=120`），先建基准、后谈优化，是否允许改常量由 P-M42-09 裁决、改造深度由 P-M42-10 裁决。

> ✅ **已裁决（P-M42-01，用户 2026-11-08）**：A/B 里「相册 CRUD 完整 UI 入口」「星标角标」虽在原路线图（08-B §A-6）归 M5/M6，但作为**「beta.2 release notes 已承诺、且只是把已有 DB 能力接上 UI」的小补全**，**纳入 M4.2**。M4.2 因此是「纯收尾 + 一点 M5/M6 前置」，不改 schema。
>
> ✅ **范围追加（用户 2026-11-08 m00172）**：D 组「图片加载速度 + 滑动更平滑展示」纳入本版；但它是**有边界的**——只在不破坏 R-M42-1（p99 ≤ 25 ms、首屏 ≤ 5 s、常量不变、不引入常驻定时器 R-M41-1）的前提下做，且**先建基准再优化**。具体口径见 §3 D 组与 §4 R-M42-1 特别说明。

## 3. 需求骨架（评审通过后展开成 16/17 的条目）

> 每条给「一句话目标 + 验收方向」，不写实现细节。

### A 组 · 展示欠账
- **M42-UI-01 星标/标签可见性**：网格照片格能按星标显示角标（与选中角标共存不打架）；查看器信息条显示该张的标签与星标。验收：打星标→网格同格可见、进查看器可见；标签同理；与 `M41-UI-09` 选中角标叠加不遮挡。
- **M42-UI-02 微缩图集圆角**：`≤48px` 档（`draw_from_atlas`）子矩形也按 8px 圆角裁剪，三布局四角一致。验收：缩到最小档，方格/纵瀑布/横瀑布四角均圆角；`grid.rs` 布局单测（列宽/行高/文件名位置）不回退。

### B 组 · 交互欠账

### D 组 · 展示性能（用户 2026-11-08 追加，先基准后优化）

> 主题域同 M4.1「展示速度」，但**不是改常量硬提参数**：M4.1 把 `TEX_UPLOAD_PER_FRAME=3` / `TEX_CACHE_CAP=120` / `SCROLLBAR=8.0` 锁死成红线正是为守住 p99 ≤ 25 ms。D 组默认**不动这些常量**，靠调度/可见性/解码/缓存复用把「出图延迟」和「滚动掉帧」做顺；要动常量须 P-M42-09 裁决并复核基准。

- **M42-PERF-00 展示性能基准与埋点（前置，先于 02/03）**：在隔离库上量出「首屏出图时间、可见区首张出图延迟、滚动帧耗时 p50/p95/p99、每帧贴图上传数、空白格率」，固化为 `03` 的 `TC-M42-PERF-*` 基线用例。验收：优化前有一组可复现数字，优化后同场景对比不劣化；**没有基准不允许改常量或改上传调度**（防止像玻璃那样「凭感觉优化、实机更差」）。
- **M42-PERF-02 图片加载速度**：可见区优先、缩略图解码与贴图上传调度更顺、减少空白格（placeholder→实图过渡不闪）。验收：首屏 ≤ 5 s 不回退；同库「可见区首张出图延迟 / 空白格率」较 `M42-PERF-00` 基线下降；`TEX_UPLOAD_PER_FRAME=3` / `TEX_CACHE_CAP=120` 不变（除非 P-M42-09 放行）；不读原图、不写照片目录（R-M42-2）。
- **M42-PERF-03 图片滑动/滚动更平滑**：滚动时贴图上传更均匀、减少单帧尖峰与掉帧、滚动步长/惯性手感稳定。验收：网格滚动 p99 ≤ 25 ms 不回退；帧耗时 p99 与掉帧率较基线下降；`SCROLLBAR=8.0` 不变；**不引入常驻 `request_repaint()` / 常驻动画定时器**（R-M41-1）；三布局（方格/纵瀑布/横瀑布）均复验。

> D 组改造深度（只做调度层 vs 动预取/缓存/上传常量）由 **P-M42-10** 定；是否允许调整锁死常量由 **P-M42-09** 定。二者未裁决前，16/17 里 D 组按「只做调度/可见性层、常量不动」写。
