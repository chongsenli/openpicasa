## 0. 里程碑定位与问题对账

M3.1 完成了界面重构（三行骨架、图标工具栏、面包屑、A 样式文件树），**功能全部勾选 PASS，但可用性评审暴露出"看得见、看不懂"的一层问题**：图标语义、分组逻辑、状态可见性、信息职责。M3.2 是一次**纯可用性改版**：

- **不新增**数据层 / 引擎层能力（延续 M3.1 约束）；
- **不推翻** M3.1 的三行骨架与视觉定稿，只在其上补语义、分组、状态与文字层级；
- 有一处**有意的版式修订**（标题迁到主区顶部，M32-UI-04），该条修订 `docs/09` §7.3 的部分结论，已在条目内显式登记。

## 1. 工具栏改造（M32-UI-01～03）

### M32-UI-01 图标含义不直观 —— 关键操作带文字，辅助操作带提示

**现状（代码事实）**：M3.1 §7.2 定稿刻意做成"无文字原型圆形图标按钮"（导入 / 幻灯片 / 编辑），语义只靠图标与部分 tooltip（排序 tooltip 显示当前排序语义）。图标全部为 `icons.rs` 矢量自绘（不引 SVG 光栅化，ADR-0004）。

**怎么改**：

1. 图库页**高频操作改为图标＋文字**：`导入图片`、`幻灯片`。文字用 12.5px 次级字号、按钮右侧紧跟图标，不再做无文字圆钮。侧栏开关按钮放到最左侧，然后放这三个按钮。
2. 搜索、排序、视图、筛选等通用操作**保留纯图标**（维持截图的右侧图标组位置），但必须带 tooltip，tooltip 文案格式统一为 `功能名 · 快捷键`（如 `搜索 · ⌘F`、`排序 · 当前：名称 ↑`）。
3. **图标换形须先核实功能**：对当前不易理解的图标（编辑、筛选、更多），先在 `topbar.rs` / `toolbar.rs` 里确认实际接线的行为，再决定是否换成通用图形；禁止按图标形状反推功能。
4. tooltip 机制复用 M3.1 已有的悬停 tooltip 实现，不新造浮层组件。
5. 版权红线不变：新图标矢量自绘、视觉重量对齐参考，不提取原版资源。

**验收标准**：

- [ ] 不点击试错，用户能说出 `导入图片`、`幻灯片` 两个按钮的用途（图标＋文字直接可读）。
- [ ] 所有仅图标按钮（搜索 / 排序 / 筛选 / 更多 / 侧栏开关 / 排布胶囊）均有可读名称的 tooltip；有快捷键者 tooltip 内含快捷键。
- [ ] 每个图标的功能与 tooltip 文案、实际行为三者一致（逐枚核对 `TopbarAction` 接线）。

### M32-UI-02 工具栏分组不清晰 —— 拆分"图库浏览"与"图片操作"

**现状（代码事实）**：M3.1 工具栏一行排开：侧栏开关 → 导入/幻灯片/编辑 → 排布胶囊 → −/+ → 搜索 → 排序/筛选/…，**没有**按"浏览设置 / 对象操作"分组；选中图片后也没有任何上下文操作栏（星标、托盘操作散落在查看器与快捷键里）。

**怎么改**：

1. 工具栏（第一行）按**截图实机布局**分为三段（组间留白分隔，不加竖线、不给每枚按钮独立圆底）：
   - **左段（对象操作）**：侧栏开关，随后为导入（截图 `⊙` 圆钮位）、幻灯片、编辑三枚图标按钮；
   - **中段（图库浏览）**：三图标排布胶囊（方格 / 纵瀑 / 横瀑，截图已高亮当前项）、−/+ 缩略图大小（**维持连体胶囊，不做滑杆**，2026-11-04 拍板，见 M32-UI-03 修订）；
   - **右段（查找与更多）**：搜索、排序、筛选、更多 `…`。

   > 原规划"工具栏只留浏览类、导入移入左段首位"按截图修订：**导入类操作保留在左段**，与截图一致；中段为视图与缩放，右段为查找与更多。

2. **选中图片后出现上下文操作栏**（浮出在网格顶部或工具栏下方，二选一在评审定稿），内容：

   > `已选 3 张` ｜ 星标 ｜ 加入托盘 ｜ 更多 ｜ 取消选择

   - 栏内**只放已实现的功能**：星标（M3 已交付，F8-01）、加入托盘（F1-19，`Ctrl+H` 语义并入按钮）、取消选择。导出 / 编辑在对应功能域交付前**不出现在栏内**（不做灰按钮假入口，与"显式占位优于假交互"原则一致，可进"更多"菜单以置灰＋说明形式出现与否，评审定）。
   - 无选中图片时**不渲染**该栏（不是隐藏为空壳）。
3. 分组表达：组间留白 ≥ 组内间距 ×2；普通按钮去掉独立圆形底与阴影（样式细则归 M32-UI-12）。
4. 低频设置（含子文件夹、全屏、方格显示文件名开关等）收进"更多"菜单；**搜索、排序入口不得**收进"更多"。
5. 星标按钮文案按当前选中集状态显示 `星标` / `取消星标`（选中集全为已加星时显示后者）。

**验收标准**：

- [ ] 用户能明确区分"改变浏览方式"（工具栏）与"处理选中图片"（上下文栏）。
- [ ] 未选中任何图片时，界面上不存在星标 / 加入托盘 / 取消选择等对象操作入口——不会误触。
- [ ] 选中 1 张、⌘ 多选 3 张、Shift 连选 5 张三种场景，操作栏计数与实际选中集一致；`Ctrl+H` 与"加入托盘"按钮效果相同。
- [ ] 搜索、排序入口在工具栏一级可见，未被收纳。

### M32-UI-03 ＋/－ 作用不明确 —— 图库改"缩略图大小"滑杆，单图另设"图片缩放"

> **2026-11-04 用户拍板修订**：M32-UI-01/02 **只调整按钮位置**，中段维持"视图胶囊＋−/+"，**不做滑杆**。本条中滑杆相关内容（第 1~4 点）取消，仅保留第 5 点（单图查看器"图片缩放"控件，独立于图库档位）与 tooltip 语义改进（`调整缩略图大小` 文案并入 −/+ 现有 tooltip，实现已具备）。`ZoomState` 既有机制不动。

**现状（代码事实）**：顶栏 −/+ 连体胶囊按 12 对数档步进（`step_log`，22～512 px，settings 表全局保存）；`⌘+`/`⌘−`/`⌘0` 同路径；`ZoomState` 的连续拖动、锚点、回滞逻辑**原样保留**（09 §6 提醒①：加滑杆直接复用，别重写）。查看器（viewer.rs）M3.1 未动，其内缩放与图库密度共用部分心智。

**怎么改**：

1. 图库页将 −/+ 胶囊替换为**滑杆控件**：`小图标 ───●──── 大图标`，两端各配一枚小图标（不可省略），tooltip 固定文案 `调整缩略图大小`。
2. 拖动**实时**调整缩略图尺寸与列数；落点吸附到既有 12 档（吸附与回滞逻辑沿用 `ZoomState`，防止打滑）；`⌘+` / `⌘−` / `⌘0` 行为不变，且滑杆位置同步反映当前档位。
3. 范围沿用 22～512 逻辑 px；拖动中不换纹理（松手结算）机制保留。
4. 当前档位持久化继续走 `settings` 表（全局保存，跟库走）。
5. **单图查看器另设"图片缩放"控件**：显示当前百分比（`100%`）＋"适应窗口"＋放大 / 缩小；其状态与图库缩略图档位**互相独立、互不写入对方**。
6. 滑杆与 −/+ 的替换属绘制层改动，不动缩略图管线与纹理档选择。

**验收标准**：

- [ ] 图库内该控件只改变缩略图大小与列数，任何情况下不改变原图显示比例的语义。
- [ ] 拖动滑杆列数实时变化、无闪烁；松手后档位吸附；重启后保持上次档位。
- [ ] 查看器内调整"图片缩放"到任意百分比后返回图库，图库缩略图档位与进入前一致；反向亦然。
- [ ] `⌘+` / `⌘−` / `⌘0` 与滑杆位置始终同步。

## 2. 布局改造（M32-UI-04～05）

### M32-UI-04 顶部留白多、标题与操作脱节 —— 主内容区建立统一的标题与控制栏

**现状（代码事实）**：M3.1 §7.9 后顶栏为 96px 双行（上行红绿灯＋面包屑，下行图标组）；当前文件夹标题与 `N 张 · 日期跨度` 副标题在**左栏顶部标题区**（`sidebar.rs`），不在图片区上方；搜索框展开在上行右端。

**怎么改**：

1. **标题迁到主内容区顶部**，按**截图实机布局**建立主区标题区（该条修订 `docs/09` §7.3"标题区在左栏"的结论，左栏保留文件树，不再承担标题）：

   ```text
   窗口栏（工具栏：侧栏开关 / 对象图标 / 视图胶囊 / −·+ / 搜索·排序·筛选·…）
   ────────────────────────────────────────────────
   侧栏      │  所有照片                        ← 15px 主色，左对齐
   所有照片 40│  40 张 · 2010 年 3 月            ← 11px 次级灰
   最近更改  │  ─────────────────────────────
   星标     │  图片网格（唯一滚动区）
   ```

   - 主区顶部为**两行左对齐**：第一行语境标题（`所有照片` / 文件夹名 / `搜索"海"` / `星标`），第二行副标题 `N 张 · 拍摄年月`（口径见 M32-UI-09）。截图中该标题当前在左栏顶部，本条将其右移到网格上方，消除顶部留白。
   - 标题区**不带右侧操作按钮**（操作已在工具栏，不在标题行重复）。

2. 文件夹、搜索结果、星标等语境复用同一位置（文案规则见 M32-UI-09）。
3. 缩减顶栏无功能留白：96px 双行顶栏收敛为单行业务栏（红绿灯嵌入方式保留，`traffic_w = 78` 为 macOS 专用补偿值，改布局前按 09 §6 提醒②在非 macOS 复核）；图片区域整体上移。
4. 标题两行**固定**，滚动只发生在图片网格（网格虚拟化与视口锚点保持机制不动）。
5. 面包屑不删除：收进主区标题行（`图库 / 祖先… / 当前` 作为标题的语境前缀或次级行，评审定稿），祖先段可点击跳转行为保留（`TopbarAction::PickFolder`）。

**验收标准**：

- [ ] 进入任意页面（文件夹 / 搜索结果 / 星标 / 所有照片），用户在主区顶部**立即**确认当前位置与图片数量；可用操作在工具栏一级可见。
- [ ] 主区标题区为两行左对齐（标题＋`N 张 · 拍摄年月`），右侧无操作按钮；顶部空白高度有量化上限（设计稿给值，基线比对 ≤2px）。
- [ ] 滚动图片时标题行与控制行不动；`docs/ui-baseline` 截图基线按 ADR-0006 流程更新。

### M32-UI-05 侧栏与主区域空间分配不合理 —— 侧栏可调，网格自适应

**现状（代码事实）**：侧栏宽度固定；M3.1 有侧栏开关（收起/展开，会话级状态、不进偏好）；网格列数随缩略图档位变化。

**怎么改**：

1. 侧栏右缘支持**拖动调宽**，限定最小 / 最大值（设计稿定值，建议 min ≥ 文件树最长常规行不换行的宽度、max ≤ 窗口 40%）。
2. 保留"显示 / 隐藏侧栏"开关（现状已有），并**把侧栏宽度与显隐状态写入偏好**（落自有数据库 settings 表，禁写照片目录）。
3. 窄窗口（低于阈值，设计稿定值）自动折叠侧栏，优先保证网格可用宽度；展开动作有明确入口。
4. 网格列数随"可用宽度 × 缩略图档位"自动变化；**格间距（`CELL_GAP`）与边距（`GRID_PAD`）保持常量**，不为填满行宽放大图片。
5. 最后一行右侧留白不强行填满、不放大图片；行内左对齐。
6. 拖动调宽过程不触发重查询风暴（列数变化按既有的视口重算节流处理）。

**验收标准**：

- [ ] 在最小～最大窗口宽度区间连续拖动，不出现图片重叠、工具栏溢出、非必要横向滚动。
- [ ] 重启后侧栏宽度与显隐状态恢复；拖动中间态不落盘。
- [ ] 任意宽度下格间距与边距像素恒定（基线比对）。

## 3. 图片展示改造（M32-UI-06～08）

### M32-UI-06 缩略图可能裁切原图 —— 明确的"缩略图适配模式"

**现状（代码事实）**：方格视图为统一圆角单元格（圆角 8）；纵向 / 横向瀑布流按原比例布局；方格模式是否裁切需实现核对（本条首项任务即核实，禁止猜测）。

**怎么改**：

1. **先核实**方格视图当前行为：若本就完整显示，保留行为，本条转为补齐"模式说明＋混合比例回归测试"；若存在裁切，按下述交付模式开关。
2. 在"视图"设置中提供两档适配模式：
