# ADR-0004：图标用 egui 矢量自绘，不提取原版位图资产

- 状态：已采纳
- 日期：2026-10-29
- 相关：01 产品功能清单（界面还原）、`crates/picasa-ui/src/icons.rs`

## 背景

M1 的界面还原要求里有「工具栏按钮的图标位置、大小、间距与原版一致」这类条目。
还原图标有两种做法：

- **A. 从原版 Picasa 的安装包里提取 PNG/SVG**：还原度最高，但等于把 Google 的
  美术资源打进我们的仓库。原版已停止分发，资源没有明确的开源许可，不能因为「找不到权利人」
  就当作可以用。
- **B. 用图标库（Lucide / Feather）**：许可清晰（ISC/MIT），但要引入 `resvg`（MPL-2.0）
  做 SVG 光栅化，会在二进制里多带一个渲染引擎，且 MPL 的弱 copyleft 需要额外的合规说明。

## 决定

采用**第三种**：13 个图标全部用 `egui::Painter` 的线段/圆弧自绘（`icons.rs` 里的
`draw(painter, icon, rect, color, stroke)`），每个图标 5–20 条绘制指令。

- 尺寸通过 `rect` 参数决定，`stroke` 参数决定线宽 → 在 Retina 上天然清晰（矢量路径，
  由 GPU 光栅化，不依赖位图缩放）。
- 不引入任何 SVG/位图渲染依赖，`Cargo.toml` 里没有 `resvg` / `usvg` / `tiny-skia`。
- 图标形状按「功能语义」重画（返回箭头、加号文件夹、放大镜、网格尺寸、托盘、垃圾桶……），
  与 01 文档记录的**位置与尺寸**对齐，但不逐像素复制原版图形。

## 后果

- 合规上干净：仓库里没有任何来源不明的美术资源，全部是代码。
- 还原度上有一处已知差距：原版少数图标是**填充式**（实心），我们统一用描边。
  这属于 03 §5A 里「图标风格差异可接受，位置/尺寸/配色必须一致」的范围。
- 后续如果 PM 拿到授权素材，替换点很集中：只改 `icons.rs` 的 `draw` 分支，
  调用方（toolbar / sidebar / viewer）不需要动。
