# ADR-0006：界面还原用「窗口自截图 + 像素探针」做可复现的基线

- 状态：已采纳
- 日期：2026-10-29
- 相关：03 §5A（界面还原）、`crates/picasa-ui/src/capture.rs`、`tools/pngprobe.py`

## 背景

03 的 5A 要求逐个核对「工具栏高度、单元格边长、间距、左栏宽度、状态栏高度」这些**像素级**条目。
人工核对的做法是：打开原版 Picasa 截图 → 打开我们的窗口 → 肉眼比较。问题在于：

- `screencapture` 需要「屏幕录制」授权，而且会把别的窗口一起拍进来；
- 拿到整屏像素后必须**反推窗口矩形**才能比较，反推错一次就会把「栅格是 6 列」
  看成「4 列」——这不是假设，实现过程中确实发生过，并因此误判出一个不存在的 bug；
- 不同机器的缩放设置不同，别人复现不了。

## 决定

1. **窗口自截图**：应用自己向 eframe 要本窗口的帧缓冲
   （`Context::request_screenshot` → `ViewportCommand::Screenshot`），
   写成 PNG 后自动关窗。触发方式是两个环境变量：

   ```bash
   OPENPICASA_SCREENSHOT=/tmp/shot.png OPENPICASA_SCREENSHOT_WARMUP=50 OpenPicasa
   ```

   `WARMUP` 是必要的：缩略图每帧只上传 3 张，第 1 帧一定满屏占位灰。
2. **像素探针**：`tools/pngprobe.py`（纯标准库，自己解 zlib + 反过滤）提供
   `--row y`（沿一行输出同色连续段）、`--rect x0,y0,x1,y1`（区域主色）、`--dark`（深色块包围盒）。
   于是「左栏宽度 = 220」可以写成一条命令的断言，而不是一句描述。
3. **调试入口**：`OPENPICASA_OPEN_INDEX=N` 让应用启动后自动打开第 N 张的查看器。
   查看器只能靠双击进入，没有这个入口，「查看器的界面还原」就永远没有基线。

## 后果

- 5A 的核对从「凭眼睛」变成「量数字」。例如实测结果：
  工具栏 68、左栏 220、栅格起点 236（=220+16）、单元格 144、间距 10、
  滚动条 8、分组头 26、提示框底部距窗口底 48 —— 全部与 `theme.rs` 常量一致。
- 代价：`Capture` 多了一个只在环境变量存在时激活的分支，两条调试环境变量需要
  在 README 里写明用途（否则会被当成隐藏后门）。
- 三处入口都是**只读**的：不写照片目录、不改索引，符合 R-1。
- 遗留：截图是物理像素（Retina 下为逻辑的 2 倍），探针用 `--scale 2` 换算；
  跨机型比较时需要把缩放系数一起记录。
