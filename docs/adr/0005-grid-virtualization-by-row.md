# ADR-0005：栅格虚拟化按「行号」而不是「分组边界」切分

- 状态：已采纳（由实测缺陷驱动）
- 日期：2026-10-29
- 相关：02 §8.2、`crates/picasa-ui/src/grid.rs`

## 背景

02 文档要求中央栅格在 10 万张照片下仍能 60fps，做法是「只给视口附近几十个单元格建 rect」。
第一版实现是这样算可见区间的：

```text
找到第一个"底部超过视口顶部"的分组 → 取它的 first
找到最后一个"顶部未超过视口底部"的分组 → 取它的 first + count
```

这个写法在「照片分散在很多天」时是对的，因为每个分组只有几张，整组返回也不会多。
但只要出现**一个超大分组**——同一天连拍 3000 张，或者从别的软件批量导入、日期被统一刷成同一天——
它就会把这个分组整体返回，于是每帧仍然要给 3000 张缩略图建 rect，虚拟化完全失效。

## 发现过程

单元测试 `visible_range_is_bounded_and_covers_viewport`（1000 张同一天）直接失败：

```
可见区间过大：1000
```

这条断言就是为此写的：如果只断言「区间非空」，这个 bug 会一路带到真机上，
表现成「照片一多就卡」，而排查方向会被误导到纹理上传或 SQL 上。

## 决定

`visible_index_range` 改成两级：

1. 先定位视口命中的首/末**分组**（O(分组数)，分组数 ≈ 天数）；
2. 再在分组内部把 `viewport.y` 按 `cell_h + gap` 换算成**行号**，
   用 `first + row * cols` 得到索引，两侧各留一行 overscan。

```text
first = g0.first + floor((top - g0.y - header) / pitch) * cols   （再减一行）
last  = g1.first + ceil((bottom - g1.y - header) / pitch) * cols （再加一行）
```

顺带修掉两个相关缺陷：

- **普通位置的分组头从来没被画过**。原实现只画了吸顶头，于是每个分组上方多出一条
  26px 的空白带、日期不可见。现在先按 `groups_in_range` 画普通头，吸顶头仍在最后画
  （顺序不能反，否则被单元格盖住）。
- 视口完全在内容下方时返回空区间，避免「滚动条拖到底部后仍返回上一屏索引」。

## 后果

- 1000 张同一天：可见区间 < 200，虚拟化恢复。
- 多分组时按行裁剪，比原来「整组」更省。
- 新增 ADR 之外的两个测试：`huge_single_group_stays_virtualized`、
  `viewport_below_content_yields_empty_range`，把这两个坑钉住。
- 遗留：`groups_in_range` 用的是 `group_of`（二分），每个可见分组调一次，代价可忽略。
