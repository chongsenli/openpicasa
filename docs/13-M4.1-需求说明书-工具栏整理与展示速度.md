## 0. 里程碑定位与问题对账

### 0.1 交付核心

M4 完成了照片检索、整理与索引管理，**功能全部勾选 PASS，但实机评审暴露出「对象操作够不着、展示不一致、多选不顺手」的一层问题**：

- 收藏 / 说明 / 标签 / 照片托盘四类功能**数据层与右键菜单、独立 Window、筛选面板都已接通**（`docs/11` §13.1），但**工具栏一级没有入口**，用户必须右键或开弹窗才能用；
- 方格缩略图有圆角软阴影，两个瀑布流却是直角 + 1px 灰框，**三种布局观感割裂**；
- 方格默认档照片偏高、文件名离图太远，一屏看不了几张；
- 默认工具栏图标钮「白底白图」对比度弱，难识别；
- 筛选面板里混进了不该属于「筛选」的批量打标签，照片类型没有「全部」；
- 多选只有 ⌘/Shift，**鼠标按住拖选（框选）完全没做**（`08` §四顺延项）。

M4.1 是一次**展示层 + 交互层修复**：

- **不新增**数据层能力：收藏 / 说明 / 标签 / 托盘的 DB 表、批量 API（`crates/picasa-db/src/lib.rs:2593-2709`、`crates/picasa-core/src/library.rs:733-1018`）**全部复用**；
- **不推翻** M3.2 的三行骨架与三段工具栏，只在其上增按钮、改绘制、补交互；
- **不回退** M4 §13.7/13.8 的性能修复（EXIF 三段式后台、左栏缓存、release 规避 panic）。

## 1. 工具栏对象操作（M41-UI-01 / 05 / 08）

### M41-UI-01 新增「收藏 / 说明 / 标签 / 照片托盘」四个按钮（位置按 #4 定稿）

**现状（代码事实）**：

- 顶栏左段只有 4 枚按钮，第 4 枚「编辑」是 `TopbarAction::Placeholder("编辑（下一版开放）")`（`topbar.rs:228-232` → `app.rs:1993-1995` 弹 toast），其后**直接接中段排布胶囊**（`topbar.rs:184-196` 定位）。
- 四类功能的数据层与 UI 入口都已存在，但**分散且与选中集脱节**：
  - 收藏：`photo_ctx` 菜单 → `batch_set_starred_ids(vec![id], !starred)`（`app.rs:2655-2660`）；筛选面板「对所选：★收藏/☆取消」→ `lib.batch_set_starred`（`app.rs:2798`）。
  - 说明：右键 → `caption_editor = Some(photo_id)` → `egui::Window "照片说明"`（`app.rs:2695-2719`）。
  - 标签：右键 → `tag_editor = Some(photo_id)` → `egui::Window "照片标签"`（`app.rs:2721-2760`）；筛选面板「批量标签」→ `lib.batch_add_tag`（`app.rs:2809-2811`）。
  - 托盘：`⌘H` → `lib.to_tray()`（`shortcuts.rs:74-76`）；`lib.tray: Vec<i64>` 存 `Preferences.tray`（`prefs.rs:35-36`）。
- `Icon` 枚举已有 `Heart`（收藏心形，`icons.rs:64, 334`）、`Tray`（`icons.rs:37, 174`）、`Info`（`icons.rs:41, 191`）；**没有 Star 图标，也没有 Tag / Caption 图标**。
- `Library.selection: HashSet<i64>` 已天然多选（`library.rs:130`）。

**怎么改**：

### M41-UI-06 工具栏默认态玻璃态（v1.1 · 按 Tessera UI Fluid Glass 风格）

> **v1.1 修订（2026-11-06，用户指定参考）**：用户给出 [Tessera UI `Fluid Glass`](https://tessera-ui.github.io/zhHans/components/fluid_glass.html) / [`Glass Button`](https://tessera-ui.github.io/zhHans/components/glass_button.html) 页面，要求「按照这个网页的空间，实现按钮的玻璃态」。本节据此**重写 v1.0 的「半透明白 + 阴影」方案**——v1.0 的 `white_alpha(.72)` 叠在纯白 `toolbar_bg` 上，背后没有任何可透内容，半透明等于白，**看不出空间感，不是玻璃**。v1.1 对齐 Tessera 的「液态玻璃」六要素。

**参考事实**（Tessera UI，Rust + wgpu 即时模式 UI，MIT/Apache-2.0）：

| 来源 | 明确写出的能力 |
| --- | --- |
| [Fluid Glass](https://tessera-ui.github.io/zhHans/components/fluid_glass.html) | `fluid_glass(args, ripple_state, child)`；可配「颜色、边框、阴影、圆角、**模糊强度、折射率**」；具有「点击交互、**折射扭曲背景、高斯模糊、色散、水波动画**」；是其他玻璃组件的基础 |
| [Glass Button](https://tessera-ui.github.io/zhHans/components/glass_button.html) | 基于 `fluid_glass`；「背景颜色、边框、**折射、色散**」+「点击交互、**水波动画**」 |
| [`glass_button_example.gif`](https://tessera-ui.github.io/glass_button_example.gif)（逐帧取样） | 玻璃后面是**彩色背景**（红 `(195,6,36)` → 透过玻璃变浅粉 `(244,177,179)`）；边缘明显**折射变形**；上缘亮、下缘暗；点击有水波纹 |

**现状（代码事实）**：`icon_btn`（`topbar.rs:400-437`）默认态是**不透明白圆底 + 极淡软阴影**：

```rust
painter.add(theme.control_shadow.as_shape(rect, ICON_D / 2));       // blur 3, black_alpha 36
painter.rect_filled(rect, ICON_D / 2, Color32::WHITE);                // 不透明白
```

`toolbar_bg = WHITE` 不透明（`theme.rs:161`），注释自称「毛玻璃观感的来源」但**没有任何半透明、模糊或背景采样**（`theme.rs:102, 170-176`）；`macos.rs` 与 `lib.rs:65-80` 未启用 `NSVisualEffectView` / vibrancy。即**既没有玻璃，也没有可供玻璃透的内容**。

**怎么改**（六要素，§7 P-M41-07 已按本方案裁决）：

1. **先给玻璃一块「可透的内容」——顶栏底图（本版新增，最关键）**：
   - `toolbar_bg` 由纯 `WHITE` 改为**极淡渐变彩色底**（两次 `RectShape` 叠加：淡粉 `#FFEBE8` → 淡蓝 `#EBF4FF` → 淡橙 `#FFF5E8`），再叠两处低透明度径向光斑（蓝 `selected@20%` / 橙 `#E8A33D@18%`）。
   - 这是 Tessera 动图里「红底透过玻璃变粉」的同款前提：**没有底图，半透明永远等于白**。底图必须极淡，保证 `#2A2A2A` 图标对比度 ≥ 4.5:1（`10` M32-UI-13）。
2. **按钮玻璃片（`icon_btn` 重写）**：

   | 层 | 内容 | egui 落地方式 |
   | --- | --- | --- |
   | ① 折射/模糊底 | 顶栏底图**高斯模糊一次**（≈10px）+ 轻微增饱和 | 见第 3 点「离屏底图纹理」，贴到按钮 rect 的 `RectShape::with_texture` |
   | ② 半透明染色 | `Color32::from_white_alpha(0.30)`（Tessera 动图：红底→浅粉） | `RectShape::filled(rect, radius, tint)` 叠在 ① 上 |
   | ③ 镜面高光带 | 按钮**上半部**一条 `white_alpha(.55)→0` 的竖向渐变 | 两层半透明 `RectShape` 近似 |
   | ④ 厚度 inset | 顶白高光 / 底黑 10% / 左右侧高光 / 1px 内圈，共 5 层 | `painter.rect_stroke` + `Shape::line_segment` |
   | ⑤ 色散 | 左右各一道 `rgba(255,120,120,.22)` / `rgba(120,170,255,.22)` inset 边 | 两条 1px 半透明描边（近似 Tessera dispersion） |
   | ⑥ 亮边/暗底边 + 外阴影 | `white_alpha(.55)` 亮边、`black_alpha(.08)` 底边；`control_shadow` blur 3→4、offset [0,1]→[0,4] + 1px 近阴影 | `topbar.rs:416-422` 改写 |

   - 图标色 `toolbar_icon = #2A2A2A` 不变；**不使用** `NSVisualEffectView`（P-M41-07）。
3. **egui 无 `backdrop-filter` 的落地路径（实现红线）**：
   - egui/epaint **不能**对「已绘制的背景」做实时模糊（无 framebuffer 采样）。因此**不逐帧模糊**：在 `topbar.rs::show` 开头，把顶栏底图 + 径向光斑**离屏渲染到一张小纹理**（宽 = 顶栏宽，高 = `TOPBAR_H`，最大 1280×96），做一次 10px 盒式/高斯模糊，**缓存为 `glass_underlay: TextureId`**；
   - 缓存失效条件：顶栏宽度变化、侧栏宽度变化（左段按钮位置变）、主题/深浅切换、窗口 DPI 变化。**其余帧零重算**；
   - 每个按钮只把这张纹理的**对应子矩形**贴进自己的 rect（`RectShape::with_texture`），再叠 ②～⑥。折射扭曲用「子矩形 UV 轻微偏移」近似（可选，P-M41-07 默认不做逐像素折射）。
   - **性能红线**：模糊底图每帧只生成 0 或 1 次、不新增每帧 `request_repaint()`、不新增缩略图纹理上传；`TEX_UPLOAD_PER_FRAME=3` / `TEX_CACHE_CAP=120` 不变（R-M41-2）。
4. **状态层级 + 水波纹**（Tessera `RippleState`）：

   | 状态 | 染色 | 模糊 | 边缘 / 动作 |
   | --- | --- | --- | --- |
   | 默认 | 白 30% | blur 10 + sat 1.35 | 亮边 + 暗底边 + 5 层 inset |
   | 悬停 | 白 46% | blur 7 + sat 1.5 | 亮边 + `translateY(-1px)` + 阴影加深 |
   | **按下** | — | — | `scale(.94)` + **从触点扩散的浅色水波圆**（0.5s，Tessera `RippleState`） |
   | 选中（♥/▣ 双态、排布胶囊当前片） | **中性灰 `#8C8C8C` 半透明 55%**（**仍可透**、v1.2 用户裁决不用粉色） | blur 10 | `#6E6E6E` 边 + 图标转白 |
   | 禁用（−/+ 端点） | 白 16% | blur 3 | `text_disabled`、无阴影、无高光 |

   - 排布胶囊 / −/+ 连体胶囊（`draw_layout_pill` / `draw_zoom_pill`，`topbar.rs:443-576`）套同一套玻璃底，避免「圆钮浮起来、胶囊还平着」的新割裂。
   - 水波纹状态 `ripple: Option<(Pos2, Instant)>` 存在 `App` 或 `TopbarOutput`，只在点击帧置位，0.5s 后自动清空；**不引入动画定时器强制重绘**（用 egui 的 `request_repaint_after` 只在波纹存活期调用，波纹结束即停，R-M41-1）。
5. **不回退**：`filter_active` 的 `theme.selected` 圆描边（`topbar.rs:314-322`）、`−/+` 端点置灰（`topbar.rs:484-495`）、tooltip 机制一律保留。

**验收标准**：

1. **状态**：`App` 新增 `marquee: Option<MarqueeState>{ start: Pos2, current: Pos2, additive: bool }`（内容坐标，见第 3 点）。`grid.rs::GridOutput` 新增 `marquee: Option<Rect>`（本帧框选矩形，内容坐标）与 `clear_selection: bool`。
2. **起手判定**：在网格**空白区域或照片上**按下左键并移动超过阈值（`DRAG_THRESHOLD = 4.0` px，`theme.rs` 新增常量）即进入框选；**不达到阈值的按下-释放仍按普通单击**处理（`M41-UI-09` 语义不破）。
   - 起手在照片上：也允许拖出框选（用户「左键按住后移动鼠标多选照片」）；起手在照片上且**未移动**才走 `click_select`。
   - `ui.input(|i| i.pointer.primary_down() / primary_released() / pointer.interact_pos())` 取屏幕坐标；`area` 的 `Sense` 改为 `Sense::click_and_drag()`（`grid.rs` 的 `ScrollArea` 输出 `response` 或单独铺一层透明 `Area`，§7 P-M41-08 定实现路径）。
3. **坐标换算**：屏幕坐标 → 内容坐标要减去 `origin`（`grid.rs` 绘制时的 `origin.to_vec2()`）并加回 `out.scroll_y`（`grid.rs:1276` 已有 `scroll_y`），再用 `layout.thumb_rect(index)` / `layout.hit_index(pos)`（`grid.rs:652-680`）求矩形与哪些格相交。
   - **判定口径**：框选矩形与缩略图 `thumb_rect` **相交即命中**（不是「完全包含」，符合 Finder / Photos 手感）；命中集合 = `layout` 可见索引 ∩ 矩形。
   - 只算**当前视口可见格**（`grid.rs` 已有 `visible range`），**不遍历全库、不逐张查库**（R-M41-1/R-M41-2）。
4. **提交**：释放左键时：
   - `additive = 起手时 ⌘/Ctrl 按住` → 命中集 `union` 进 `lib.selection`；
   - 否则 **替换** `lib.selection`（清空后插入命中集）；
   - `anchor` 更新为命中集最后一张的 index（保证后续 Shift 连选接得上，`library.rs:932-962`）。
   - 空矩形 / 只点空白：走 `M41-UI-09` 的「清空选中集」。
5. **绘制**：拖动帧在 `grid.rs` 绘制循环**最后**（吸顶分组头之后）画 `Rect`：`fill = theme.selected.gamma_multiply(0.12)` + `stroke = Stroke::new(1.0, theme.selected)`；圆角 2px。**不新增纹理、不每帧 `request_repaint()`**（拖动本身由 egui 输入驱动重绘，R-M41-2）。
6. **滚动兼容**：拖动到视口边缘**不做自动滚动**（本版非目标，§7 P-M41-09）；`ScrollArea` 的滚动手势与框选靠「起手位置 + 阈值」区分，避免抢滚轮。
7. **占位格**：`placeholder` 格「不参与选中」（`grid.rs:1110` 既有注释）沿用——框选命中集合过滤掉 `thumb_state=0/2/3` 的格。
8. **不新增数据层**：全程只改 `lib.selection`（`HashSet<i64>`）与内存 `layout`。

**验收标准**：

- [ ] 在网格空白处按住左键拖出一个矩形，松开后矩形**相交**的所有照片被选中，底栏计数与角标一致。
- [ ] 起手在照片上拖动，同样进入框选；起手在照片上**按下即松开**（移动 < 4px）仍是普通单选，不误触发框选。
- [ ] 框选时按住 ⌘：新矩形命中集**追加**到已有选中集（union）；不按 ⌘：替换选中集。
- [ ] 拖动过程中有半透明蓝色矩形 + 1px 蓝边实时跟随；松开后矩形消失，选中角标保留。
- [ ] 框选后接着 Shift 点另一张，能按新 `anchor` 正确连选。
- [ ] 框选 1 000 张可见格时无卡顿（p99 ≤ 25 ms 不回退），长跑日志零 WARN/ERROR/panic（R-M41-1）。
- [ ] 滚轮缩放 / 滚动、双击开查看器、右键单选（`M41-UI-05`）与框选互不干扰。
- [ ] 占位「待生成」格不被框选选中。

### 9.2 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 删 `photo_ctx` 时误删「打开帧豁免」通用函数 | `folder_ctx` 右键菜单复现 `78fa639` 的「打开即关闭」P0 | 只删 photo 侧，`context_menu_open_frame_exempt` 与 `folder_ctx` 单测保留并复跑（§1 M41-UI-05 第 3 点） |

---

**一句话总结**：M4.1 把 M4 已接通却「够不着」的四类对象操作**收进工具栏左段**（收藏/托盘做成跟随选中集的双态钮），把**筛选面板还原成纯筛选**、把**右键菜单退役**、补上**框选拖选**这最后一块多选底座；同时让三种布局**共用圆角贴图**、默认档**更密**、按钮样式**回退到 M4 白圆底**（玻璃态 v1.1～v1.6 的探索已按用户裁决整体撤销）——全程**零数据层改动、零 schema 迁移、零照片目录写入**，并把 M4 刚修好的性能与崩溃防御**原样守住**。

### 10.3.3 v1.6 按 Tessera 真算法加强（用户 2026-11-07 裁决）

| 项 | v1.5（近似） | v1.6（照抄真算法） | 对应 Tessera 源码 |
| --- | --- | --- | --- |
| 折射 | 6 条竖切片，抛物线 UV 偏移 | **SDF 圆角矩形梯度 = 法线** → `circle_map(1-(-sd/refraction_height))` 算折射距离 → 混入 `eccentric_factor=0.2` 的指向中心方向 → nx×ny 网格切片逐格 UV 偏移（同时有 x/y 边缘拉弯） | `pipelines/fluid_glass/glass.wgsl` 的 `shape_eval.x/yz`、`circle_map`、`refracted_direction` |

| 水波纹 | 500ms | **600ms 线性扩散**，亮度 `(1-p)*0.3` 淡出 | `ripple_state.rs`：`progress = elapsed_ms / 600.0` |

### 10.5 为什么不能「直接使用 Tessera 的 glass_button 组件」

> 用户 2026-11-07 明确要求「直接用他的按钮组件」。调研（只读 + 联网查证）结论：
> **在 eframe/egui 0.37 里技术上不可行**。依据如下，作为设计决策留档。

| 阻碍 | 事实 | 来源 |
| --- | --- | --- |
| 不同框架 | 本项目 = eframe/egui 0.37；Tessera = 另一套 wgpu + `#[tessera]` 过程宏框架。`glass_button(args, ripple_state, child)` 返回 `()`，副作用是往 **Tessera 组件树**注册节点，不是 egui `Widget` | [glass_button 文档](https://tessera-ui.github.io/zhHans/components/glass_button.html)、[fluid_glass.rs](https://raw.githubusercontent.com/tessera-ui/tessera/tessera-ui-v2.5.0/tessera-ui-basic-components/src/fluid_glass.rs) |
| 全局 runtime | `#[tessera]` 宏展开依赖 `TesseraRuntime::with/with_mut` 全局单例 + `Renderer::run(app, register_pipelines)` 帧循环；离开它组件函数无法执行 | [runtime.rs](https://raw.githubusercontent.com/tessera-ui/tessera/tessera-ui-v2.5.0/tessera-ui/src/runtime.rs) |
| 渲染后端冲突 | Tessera 2.5 用 **wgpu 27**，egui 0.37 用 **wgpu 30**；各自独占 device/queue/surface 与 winit 事件循环，eframe 不暴露可注入的 device 所有权 | [tessera-ui/Cargo.toml](https://raw.githubusercontent.com/tessera-ui/tessera/tessera-ui-v2.5.0/tessera-ui/Cargo.toml)、[egui-wgpu CallbackTrait](https://docs.rs/egui-wgpu/0.37.0/egui_wgpu/trait.CallbackTrait.html) |
| 管线不通 | egui 把 Shape 交 epaint tessellator 生成 Mesh 后由 egui-wgpu 单 pipeline 绘制；Tessera 走 `DrawCommand`/`DrawablePipeline` 注册制（`FluidGlassCommand` + `DualBlurCommand`）。egui tessellator 不认识这些命令 | 同上 + [pipeline.rs](https://raw.githubusercontent.com/tessera-ui/tessera/tessera-ui-v2.5.0/tessera-ui-basic-components/src/pipelines/fluid_glass/pipeline.rs) |

**三条替代路径的评估**：

| 路径 | 现实性 | 代价 / 风险 | 结论 |
| --- | --- | --- | --- |
| (a) 整体换 Tessera | 现实但最重 | 重写整个 picasa-ui（窗口/布局/交互/字体/持久化/文件对话框），放弃 eframe persistence；统一 wgpu 版本；周级 | ❌ 收益只为几个玻璃按钮，不推荐 |
| (b) `egui_wgpu::CallbackTrait` 自定义 WGSL pipeline | **最贴近** | 需在 `Frame::wgpu_render_state()` 上接 prepare/paint、bind group、scene texture、clip rect、DPI；egui 不提供 scene_texture，取「背景纹理」较麻烦；1~2 周 | ⏸ 顺延 M4.2，若评审要求真·屏幕空间折射再做 |
| (c) 同一 device 叠两个框架 | 不现实 | 需放弃 eframe、自己写 winit+wgpu 30 宿主并 fork Tessera 接受外部 device | ❌ |

**用户裁决**：走「保持 egui 自绘 + 按真算法加强」（§10.3.3），不换框架、不引新依赖。
