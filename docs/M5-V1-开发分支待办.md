## 三项改动的核验结果（2026-11-23）

代码本来就对，缺的是**能把规格钉死的东西**——补了四个测试，并用应用自带窗口截图

| 项 | 规格 | 代码 | 测试 | 实测像素 |
|---|---|---|---|---|
| 信息栏宽度 | 25%，夹 300–480 | `info_panel_width`（viewer.rs） | `info_panel_width_follows_prototype_ratio_with_clamps` | 窗口 1708 逻辑宽 → 面板 427.5 = **25.03%** |

约 1–2 逻辑像素；两个校准点（r=0 / r=10）给出的偏移量一致，所以**亮色 22 / 暗色 6 是可信的**。
这不是「测出来 24 所以要改成 24」——原型 `.stage img` 写的就是 22/6。

## 跨日/时区、系统主题、窄窗截断（2026-11-23 第四轮，已修 + 门禁）

三项待办核查结论与改动：

1. **跨日拍摄时间范围：不是 bug。** 需求说明书 M5-SH-02 明定「副标题只根据已加载照片算跨度」，
   现有 `photo_date_span`（crates/picasa-ui/src/app.rs，按 Local 日格式化）符合规格；原型数据
   只有字符串日期、无时区概念。但核查中发现三处**真实缺陷**并已修：
   - `year_range_seconds`（crates/picasa-core/src/library.rs）：从 UTC 改**本地时区零点**，语义明确为半开 `[start, end)`；
     原来 UTC 会把 UTC+8 下 1/1 00:00–07:59 的照片归到上一年。
   - `filter_where` / `search`（crates/picasa-db/src/lib.rs）：`BETWEEN a AND b` → `>= a AND < b`，
     否则「次年 1 月 1 日 0 点整」那张会被算进上一年。
   - `timeline_years`（crates/picasa-db/src/lib.rs）：`strftime('%Y', eff, 'unixepoch')` 补 `'localtime'`，
     与 `group_by_day` / `photo_date_span` 三处同口径；**同时补上缺失的 `WHERE` 关键字**——
     原 SQL 少了 `WHERE`，调用方 `if let Ok(years)` 静默吞掉语法错误，侧栏年份行一直缺失（最严重的隐藏 bug）。
   - 新增门禁：crates/picasa-core/tests/m5_date_boundary.rs（5 测试，跨年零点/半开/时区一致）、
     crates/picasa-db/tests/v7_filter_query.rs 追加 4 测试、crates/picasa-ui/src/app.rs `m5_date_span_tests`（3 测试）。
2. **跟随系统主题动态切换：真 bug，已修。** 原 `theme::apply` 在 `Appearance::System` 下也调
   `ctx.set_theme(Dark/Light)`，把 egui 的 `theme_preference` 钉死为非 System；egui 每帧
   `sync_window_theme()` 给 NSWindow 下发固定 appearance，winit 的 `observeValueForKeyPath`
   见到窗口 appearance 被自定义就不再发 `WindowEvent::ThemeChanged`，OS 深浅色切换传不到
   `ctx.system_theme()`，`sync_theme` 早退、配色卡住。修法：System 偏好改用
   `ctx.options_mut(|o| o.theme_preference = System)`（egui 下发 `SystemDefault` → NSWindow 无自定义 appearance），
   显式 Light/Dark 才 `set_theme` 钉死。两套 style 已由 `all_styles_mut` 各自配好。门禁：
   theme.rs `apply_system_keeps_egui_theme_preference_on_system`（钉死/恢复都测）。
3. **窄窗长文件名截断：已修。** `bad5076` 已压文件名槽位保胶囊不越界，但顶栏文件名用
   `with_clip_rect` 硬切右端（含扩展名），没有 `…`。改用 `truncate_to_width` 逐字符补省略号；
   底栏把文件名按「右侧提示 + 尾段」剩余预算截断，保证 `第 i/n 张`/尺寸/Esc 提示完整不重叠。

## 主图落影（2026-11-26 第十六轮，已修 + 门禁）

**症状**：待办里一直记着「落影强度差异没量化（应用整体略淡）」。这次真去量，发现不是「淡」，
而是**照片下缘之外一点暗带都没有**：照片底下一行的中位数从照片的 73 直接跳回背景 247，中间
零过渡；原型同位置有约 43 灰阶、3–4 逻辑像素宽的一圈。

**根因两层，缺一不可**：

1. `egui::Shadow` 的 `blur` 是**边缘向内羽化**，不向形状外发光。`spread: 0` 时阴影矩形与照片
   等大，而照片随后整块盖住它——外侧自然一点不露。所以「加 alpha」永远调不出来。
2. 「适合」把照片按窗格等比放大到某一边贴边，横图贴的是高度：照片底边正好压在 `main_pane`
   底边上，落影整条落在裁剪区外（`main_painter` 裁到 `pane`）。

**修法**：

- 新增 `shadow_room(theme)`（`crates/picasa-ui/src/viewer.rs`，亮 16 / 暗 12 逻辑像素）；
  新增 `fit_zoom(pane, iw, ih, theme)` 作为「适合」的唯一入口，先 `pane.shrink(shadow_room)`
  再等比放入。代码与测试都走它，避免两边漂移。
- 新增 `photo_shadow(theme)`：亮色 `offset [0,4] / blur 6 / spread 0 / alpha 52`，
  暗色 `offset [0,4] / blur 6 / spread 0 / alpha 110`（原型 `.stage img` 是
  `box-shadow: 0 18px 40px -16px rgba(0,0,0,.18)`；egui 的 `Shadow` 语义不同，按实测像素收敛，
  不是照抄 CSS 数字）。

**实测（原生截图 + Pillow，1280×820 @2x，白底 247 与原型一致）**：

| | 峰值暗度 | 暗带宽度 |
|---|---|---|
| 修复前 | 0 灰阶 | 0 |
| 修复后 | 48 灰阶（1180 行）→ 23 → 0 | 约 6 逻辑像素 |
| 原型 | 43 灰阶 | 约 3 逻辑像素 |

**门禁**：

- `photo_shadow_is_pushed_outward_and_downward`：`offset[1] > 0`、`blur >= 4`、`alpha > 32`、
  圆角非 0——只测「Shadow 结构存在」是测不出这个 bug 的。
- `fit_reserves_room_for_the_drop_shadow`：`shadow_room >= 8`，且 `fit_zoom` 必须**小于**
  `fit_scale(pane.size())`（真收了一圈）。

顺带清掉两处 clippy：`ui.id()` → `ui.scope_id()`（3 处 deprecated）、
`if !(a > b)` → `if a <= b`（`negated comparison`）。全量测试通过，clippy 回到 2 条预存警告，
`cargo fmt --check` 与基线一致。

## 图标换 Lucide（2026-11-26 第二十一轮，已实现 + 门禁）

**决定**：顶栏/侧栏手绘图标太丑（尤其收藏心形曾退化成「药丸」）。从
Lucide / Tabler / Heroicons / Phosphor 四套开源图标包里由产品选定 **Lucide**
（ISC 许可，线性 2px，与原型同源 Feather 系，1400+ 图标）。

**做法**：把 Lucide SVG 的几何**烘焙成 Rust 折线数据**，运行时用 egui 描边绘制。
不引入 SVG 运行时依赖，颜色跟随主题、缩放不失真（折线按目标矩形归一化）。

- 源数据：`crates/picasa-ui/assets/lucide/lucide-0.544.0-raw.json`
  （41 个槽位的原始 SVG，来自 `https://cdn.jsdelivr.net/npm/lucide-static@0.544.0/icons/<name>.svg`）
- 生成器：`crates/picasa-ui/assets/lucide/lucide_to_rust.py`
- 产物：`crates/picasa-ui/src/icons_lucide.rs`（**自动生成，不要手改**）
  —— 41 个槽位、2514 个点、约 51 KB
- 重新生成：`python3 crates/picasa-ui/assets/lucide/lucide_to_rust.py`
  然后 `rustfmt --edition 2024 crates/picasa-ui/src/icons_lucide.rs`

**转换规则**：解析 `<path d>` 的 `M/L/H/V/C/S/Q/T/A/Z`（含相对命令）与
`rect(rx)`、`circle`、`ellipse`、`line`、`polyline`、`polygon`；贝塞尔与圆弧各
展开 14 段折线、整圆 32 段、圆角 8 段/角；坐标除以 24 归一化到 `0..1`。
Lucide 有少数图标几何上首尾相接却没写 `Z`（`heart` 用圆弧收口），
生成器按「首尾点距离 < 0.01」补判 `closed`，否则实心填充会漏。

**槽位映射**（41）：Back=chevron-left、AddFolder=folder-plus、Reveal=map-pin、
Sort/SortArrows=arrow-up-down、GridSize=grid-2x2、Fullscreen=maximize、
Search=search、ChevronRight/ChevronDown、Tray=inbox、Trash=trash-2、Info=info、
Index=clock、Close=x、Folder=folder、Plus/Minus、SidebarToggle=panel-left、
ListLines=list、Ellipsis=ellipsis、Share=share、Heart=heart、Star=star、
Album=book-image、PhotoStack=images、Map=map、Video=video、Person=user、
Import=download、Slideshow=monitor-play、Edit=pencil、LayoutGrid=layout-grid、
LayoutMasonryV=columns-3、LayoutMasonryH=rows-3、Tag=tag、Caption=message-square、
Calendar=calendar、File=file、Image=image、Camera=camera。

**渲染**：`icons::draw(painter, icon, rect, color, stroke)` 保留原签名。
`stroke > 0` 走 `Shape::line` 描边（闭合子路径末尾补首点）；`stroke <= 0` 走
`Shape::Path(fill)` 实心填充 —— 收藏「已星标」态用得上。
`icons::draw_star` 仍保留（网格与查看器的小实心星标，28 px 以下的自绘星形
在这个尺寸下比描边星更清晰）。

**门禁**（`crates/picasa-ui/src/icons.rs` 的 `mod tests`，7 条全绿）：
`every_icon_has_usable_lucide_path_data`（41 个 `Icon` 变体都有非空路径、每条子路径 ≥2 点）、
`icon_points_stay_inside_the_view_box`（点落在 `-0.02..=1.02`）、
`heart_is_concave_with_a_bottom_tip_and_closed`、
`reveal_is_a_pin_with_a_bottom_tip`、
`fillable_icons_are_closed_paths`（Heart / Star 必须闭合，否则实心漏填充）、
`star_points_alternate_outer_and_inner_radius`、`draw_star_mesh_is_valid_and_single_tone`。

**顺带**：`icons.rs` 由 911 行缩到约 400 行（手绘几何全被数据表取代）；
`icons_lucide.rs` 顶部 `#![allow(clippy::approx_constant)]` —— 纯坐标数据里
偶然出现接近 `π/4` 的浮点值，不是常量。

**修：暗色图标被压扁**（2026-11-26，随 Lucide 落地一起修）

现象：暗色顶栏图标看起来横向拉宽、变扁；亮色正常。

根因有两层，都出自「非正方形按钮」：

1. `icons::draw` 把 24×24 的归一化坐标**按矩形宽高分别**映射
   （`left + x*width`、`top + y*height`）。暗色 `.ib` 是 32×28，横向被拉宽 14%。
2. 调用方先在按钮上 `rect.shrink(rect.width() * 0.28)`。`shrink` 把同一个
   像素值同时缩两个方向，32×28 缩完变成 **14.1×10.1** —— 宽高比从 1.14 恶化到 1.40。

修复：

- `crates/picasa-ui/src/icons.rs` 新增 `pub fn icon_box(rect: Rect) -> Rect`
  —— 取矩形中心的**最大内接正方形**；`draw` 改用它的边长等比映射。
- `crates/picasa-ui/src/topbar.rs` 的 `icon_btn_ex`：先 `icons::icon_box(rect)` 再
  `square.shrink(square.width() * 0.28)`。
- `crates/picasa-ui/src/viewer.rs` 信息栏字段图标同样处理。
- 门禁 `icons::tests::icons_stay_square_inside_a_non_square_button`：32×28 按钮
  → 绘制框 28×28 且与按钮同心；30×30 不变；退化矩形（高 0）不 panic。

实测（暗色首页顶栏，原生截图）：图标 bbox 宽高比从 **1.33 / 1.41 / 1.44 / 1.30**
变为 **1.00 / 1.05 / 1.09 / 1.00**，纵向补回了被压掉的高度。

**修：顶栏汉字排版不齐**（2026-11-26）

现象：顶栏汉字整体偏高，搜索框里的占位符「搜索」比左侧放大镜高出约 4.5px，
侧栏行文字在 30px 行高里也偏上。

根因：`crates/picasa-ui/src/theme.rs` 里 CJK 回退字体的 `FontTweak.y_offset_factor`
还是 M32-UI-13 时代的 `0.30`（当时按系统字体校准「顶端对齐」）。M5 换用内嵌
Inter 后 metrics 变了，实测 13px 字号下汉字仍然偏上 3.25px。

校准（实测线性关系，每 +0.25 让汉字下移约 3.5px @13px）：

| 系数 | 侧栏行文字中心（目标 136） | 面包屑中心（目标 60） | 搜索占位中心（目标 60） |
|---|---|---|---|
| 0.30（原值） | 132.75（偏上 3.25） | 59.0 | 55.5（偏上 4.5） |
| 0.05 | 129.25（偏上 6.75） | — | — |
| **0.55（采用）** | **135.75** | 61.0 | 58.5 |

另外把搜索框 `TextEdit` 的 margin 从上下各 4 改成上 5 / 下 3，补 1px。

**已知副作用**：`y_offset_factor` 会同时改变 galley 高度，底栏左段（按
`rect.center().y - galley.size().y / 2.0` 居中）因此下移约 4px。这块用户没提，
先留着；若观感不行，改成按基线对齐而不是按 galley 高度居中。

**暗色顶栏选中态改为方案 D**（2026-11-26，产品拍板）

原实现：选中底 `accent_soft`（暗色 8% 青）+ 浅灰图标 —— 在 #151515 上几乎看不出
选中；若换成实心青又太扎眼（暗房底色上会出现一块发亮的方块）。

方案 D（选定）：

- 底色：永远走中性 hover 灰（原型 `.ib.on` 的 `--hover`：亮 `#ebebec` / 暗 `#232323`）
- 前景：选中时**图标变品牌青**（暗色 `#00dfe1`；亮色取主文字色，与原型 `.ib.on` 的 `--ink` 一致）
- 禁用态仍取 `text_disabled`，不受选中规则影响

实现：`crates/picasa-ui/src/theme.rs` 的 `topbar_icon_fill` 改为「选中或悬停都取
`sidebar_hover`」，新增 `topbar_icon_color(enabled, selected)`；
`crates/picasa-ui/src/topbar.rs` 的 `icon_btn_ex` 改用它。

排布胶囊（`.seg`）本来就是「`seg_active` 底 + `selected` 图标」，与 D 语义一致，未改。

门禁 `theme::m5_theme_metrics_tests::topbar_selected_icon_uses_neutral_fill_and_brand_color`：
钉住「选中底 == sidebar_hover 且 != selected」与「暗色选中图标 == selected」。
